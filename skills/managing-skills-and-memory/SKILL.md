# Managing Skills and Memory with Cortex

Cortex (https://github.com/mz00m/cortex) keeps one **vault** of skills and memory and
links every agent on every device to it. Use it instead of hand-copying
SKILL.md folders or pasting the same preferences into CLAUDE.md, AGENTS.md and
GEMINI.md.

## When to use

- "Where is skill X?" / "Which agents have skill X?"
- "Make this skill available in Codex / Cursor / my agent too"
- "Remember this everywhere" / "Sync my memory to my other machine"
- "Import what ChatGPT knows about me" / "Give me something to paste into ChatGPT"
- Setting up a new device

## Commands

Run `cortex …` (install with `npm install -g @mz00m/cortex` or `npm link` from a checkout).
Add `--json` when you need to parse the result.

| Goal | Command |
|---|---|
| Overview of vault, device, agents | `cortex status` |
| Skill × agent matrix, plus skills not yet in the vault | `cortex skills` |
| Bring an agent's skill into the vault | `cortex adopt <agent> <skill> [--bundle <dir>]` |
| Put a vault skill into agent(s) | `cortex install <skill> [agent\|all] [--mode symlink\|copy]` |
| Remove from an agent | `cortex uninstall <skill> <agent>` |
| List / add memory | `cortex memory` · `cortex memory add "<title>" --body "…" --tags a,b [--agents x,y] [--scope project:name]` |
| Pull an agent's memory files into the vault | `cortex memory import <agent>` |
| Paste text as memory | `printf '…' \| cortex memory import --text - --source chatgpt` |
| Write vault memory into agents' memory files | `cortex memory push [agent\|all]` |
| Text bundle for ChatGPT / a system prompt | `cortex memory export [agent]` |
| Pull/commit/push the vault (git mode) | `cortex sync` |
| Change a setting | `cortex config storage.mode git` · `cortex config storage.gitRemote <url>` |
| Web UI | `cortex serve` → http://localhost:4747 |

Agent ids: `claude-code`, `codex`, `opencode`, `cursor`, `gemini`, `chatgpt`, `instinct` (custom).

## Rules

- **Adopt before install.** A skill must be in the vault before it can be installed elsewhere. `cortex skills` lists what is adoptable.
- **Never edit inside the `<!-- cortex:begin -->` … `<!-- cortex:end -->` block** in CLAUDE.md / AGENTS.md / GEMINI.md. It is regenerated by `memory push`. Edit the vault item instead (`vault/memory/<id>.md` or `cortex memory add`).
- **Diverged means a decision.** If `cortex skills` shows ⚠️ for a skill, the agent's copy differs from the vault. Ask the user which wins, then `cortex install <skill> <agent>` (vault wins) or use the UI's *pull* (agent wins).
- **Scope memory honestly.** Project-specific facts get `--scope project:<name>`; only `global` items are pushed into agent memory files.
- After `memory push` or `install`, tell the user which files were written (the command prints them).

## Where things live

- Vault: `~/.cortex/vault` by default (`skills/`, `memory/`, `devices.json`)
- Per-device config: `~/.cortex/config.json` (vault path, storage mode, link mode, agent paths)
- Tests: `npm test` in the cortex checkout
